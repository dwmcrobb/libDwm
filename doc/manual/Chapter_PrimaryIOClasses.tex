\chapter{Primary I/O Classes}
There are several primary I/O classes in libDwm.  Each is used with
a particular type of source and sink.

\begin{minipage}{\textwidth}
\begin{itemize}[noitemsep,nolistsep]
\item[] \hyperref[section:DwmStreamIOClass]{\texttt{Dwm::StreamIO}} is used
  with C++ iostreams (\texttt{std::istream} and \texttt{std::ostream}).
\item[] \hyperref[section:DwmFileIOClass]{\texttt{Dwm::FileIO}} is used
  with \texttt{FILE}s (\texttt{<cstdio>}).
\item[] \hyperref[section:DwmDescriptorIOClass]{\texttt{Dwm::DescriptorIO}}
  is used with UNIX file descriptors.
\item[] \hyperref[section:DwmBZ2IOClass]{\texttt{Dwm::BZ2IO}}
  is used with bz2 streams (\texttt{BZFILE}s opened via
  \texttt{BZ2\_bzopen()}).
\item[] \hyperref[section:DwmGZIOClass]{\texttt{Dwm::GZIO}}
  is used with gz streams (\texttt{gzFile}s opened via
  \texttt{gzopen()}).
\end{itemize}
\vspace{1em}

When adding I/O support for your own data type (struct or class),
\texttt{Dwm::StreamIO} support would typically be the first target.
That's largely because for fixed length types, all of the other
I/O classes can be supported via an intermediate pass through
\texttt{Dwm::StreamIO} with a \texttt{std::stringstream} as a
data buffer.

\end{minipage}

\begin{minipage}{\textwidth}
\section{\ttfamily Dwm::StreamIO}\label{section:DwmStreamIOClass}
\begin{tabular}{ll}
  source type: & {\ttfamily std::istream} \\
  sink type: & {\ttfamily std::ostream} \\
\end{tabular}
\vspace{1ex}

\texttt{Dwm::StreamIO} provides static functions and function
templates to read and write from/to C++ iostreams.  Conceptually,
the primary interface looks like four static member function templates:
\vspace{1ex}
\color{darkblue}
\begin{fnverb}
  namespace Dwm {
    class StreamIO {
    public:
      template <typename T>
      static std::istream & Read(std::istream & is, T & t);

      template <typename T>
      static std::ostream & Write(std::ostream & os, const T & t);

      template <typename... Args>
      static std::istream & ReadV(std::istream & is, Args & ...args);

      template <typename... Args>
      static std::ostream & WriteV(std::ostream & os, const Args & ...args);
    };
  }
\end{fnverb}
\color{black}
\vspace{1ex}

The actual implementation uses many function and function template
overloads for \texttt{Read()} and \texttt{Write()}.  It can't
automatically read and write any type \texttt{T}; a data type must
either be directly supported or meet the requirements of
\hyperlink{concept:HasStreamRead}{\ttfamily Dwm::HasStreamRead}
and \hyperlink{concept:HasStreamWrite}{\ttfamily Dwm::HasStreamWrite}.
\vspace{1ex}

Note that \texttt{ReadV()} and \texttt{WriteV()} are just convenient
variadic function templates that will read or write multiple objects
in sequence.
\vspace{1ex}

\subsection{Using {\ttfamily Dwm::StreamIO} with user defined types}
If a user-defined type provides the following two public members,
{\ttfamily Dwm::StreamIO} will utilize them to read and write instances
of the user defined type:
\vspace{1ex}

\begin{itemize}[noitemsep,nolistsep]
\item[] \conceptfuncsig{std::istream \& Read(std::istream \& is)}
\item[] \conceptfuncsig{std::ostream \& Write(std::ostream \& os) const}
\end{itemize}
\vspace{1ex}

See the \hyperlink{concept:HasStreamRead}{\ttfamily Dwm::HasStreamRead}        
and \hyperlink{concept:HasStreamWrite}{\ttfamily Dwm::HasStreamWrite}
concepts for the semantic requirements of these members.
\end{minipage}
